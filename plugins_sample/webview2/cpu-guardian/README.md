## 二、 前置环境要求与官方 XTU 安装指南

### 1. 为什么必须安装官方 XTU 7.x 底座？
在现代 Windows 11 安全架构下，内核调压驱动（`iocbios2.sys`）**绝对不能作为一个孤立的 NT 服务由脚本裸起**（否则会导致驱动在寻址 ACPI 设备对象时指针踩空，引发致命的 `0x50` `PAGE_FAULT_IN_NONPAGED_AREA` 内核蓝屏）。

它必须依附于主板 ACPI 设备树（`SWC\XTUCOMPONENT` 扩展滤镜），由原厂安装程序合规注入。因此，OpenRevo 坚决不做危险的第三方内核裸注入，必须以 Intel 官方微软 WHQL 认证的底层驱动服务（`XTU3SERVICE`）作为安全通信底座。

### 2. 官方底座下载指引（切勿下错版本！）
- **官方唯一下载链接**：[Intel Extreme Tuning Utility (Intel XTU) 下载中心](https://www.intel.com/content/www/us/en/download/17881/intel-extreme-tuning-utility-intel-xtu.html)
- ⚠️ **至关重要的版本避坑声明**：
  - 针对 **13代 / 14代酷睿处理器（如 13900HX / 14900HX）**，请务必下载并安装 **7.x.x 稳定版本**（如 `7.14.2.x`）！
  - **切勿下载 10.x.x 版本！** 10.x.x 是仅面向最新 Core Ultra / Arrow Lake 架构的专用包，在 13/14 代机器上会直接报错无法安装。

### 3. 纯净无感运行机制（零窗口打扰，零额外常驻）
官方 XTU 7.x 在设计上极其克制：
- 安装完成后，开机**仅注册后台系统服务 `XTU3SERVICE`，根本不会在“启动应用”或“计划任务”中自启任何前台窗口或托盘**；
- 您日常**完全不需要手动打开原版 XTU 客户端**；
- 您只需像往常一样打开 OpenRevo 的“CPU 防缩卫士”，插件就会自动在后台与底层的 `XTU3SERVICE` 建立通信，实现 100% 纯净、无窗口打扰的硬件级守护！

## 三、 预设档位设计哲学

本插件针对 13900HX / 14900HX 等高发缩缸处理器的电压-频率曲线（VID Curve）专门验证了甜点防线：

### 1. 稳态长寿档 (极力推荐)
- **大核睿频削峰**：全核倍频截断至 `53x (5.3 GHz)`。避开 5.4GHz~5.8GHz 高频死区（该区间功耗陡增但性能边际收益递减，是 1.50V+ 死亡瞬变电涌的源头）。
- **核心电压偏移 (Core Voltage Offset)**：`-60 mV`，整体拉低 VID 曲线，满载核心降温 8~12℃。
- **缓存电压偏移 (Ring Voltage Offset)**：`0 mV`（14代 HX 系统运行时受微码保护锁定下限为 0，负压由用户 BIOS 中设置的硬件基准如 `-50 mV` 持续生效）。
- **供电瞬变电流上限 (Core IccMax)**：限制在 `280 A`（Intel Baseline 官方推荐基线，斩断大动态突发过流）。

### 2. 轻度防浪涌档
- **大核睿频**：保留高频响应，全核截断至 `55x (5.5 GHz)`。
- **核心电压偏移**：`-40 mV`。
- **供电瞬变电流上限**：`307 A`。适合需要极高单核响应、体质较好的机器。

### 3. 原厂默认基线档
- 清除所有电压偏移与倍频截断，无条件将所有寄存器安全恢复至出厂 BIOS 初始状态。

## 四、 常见问题与排错

### Q1: 提示“检测到电压调校通道受限（Windows VBS 虚拟化安全拦截）”？
**原因**：Intel 原厂安全机制规定，当 Windows 开启了【基于虚拟化的安全性 (VBS / 核心隔离)】时，若底层未放开 Undervolt Protection (UVP)，系统将拦截所有 MSR 调压写操作。
**解除方法**：
1. 打开 Windows 设置 -> 隐私和安全性 -> 设备安全性 -> 【核心隔离】；
2. 将【内存完整性】关闭（或以管理员运行 `bcdedit /set hypervisorlaunchtype off`）后重启电脑；
3. 重启后即可彻底解锁调压通道（且消除虚拟化损耗，游戏帧率通常可提升 3%~5%）。

### Q2: 调压参数是“累加”的吗？按两次稳态档会变成 -120mV 吗？
**绝对不会！**
Core Voltage Offset 是寄存器的“绝对目标设定值（Absolute Bias）”，并非相对增量。无论按多少次稳态档，写入寄存器的始终是目标值 `-60 mV`；切到轻度档写入的是目标值 `-40 mV`，绝不发生物理累加。

### Q3: 为什么切换或刷新后稳态档按钮置灰？
这属于正常防呆保护机制。当硬件实机状态已经与当前预设完全相符时，对应预设按钮会锁定为 `✓ 当前运行中`（置灰），防止二次重复下发造成无谓开销。拖动下方微调滑块改动参数后，预设按钮将自动解锁。

## 五、 插件架构与开发者说明

- `manifest.json`：插件标准清单，声明伴生服务 `revo-xtu-bridge.exe` 端口（18980）与权限。
- `index.html`：极简纯原生前端，严格遵循 OpenRevo Design System CSS 规范（深色高对比度、圆角与主题适配）。
- `sidecar/revo-xtu-bridge/`：C# 编写的轻量 REST 伴生桥接，对外提供 `/api/probe`、`/api/get`、`/api/apply`、`/api/reset` 等标准化 JSON 接口，负责跨进程与官方 `XTU3SERVICE` 建立 WCF 命名管道。
- **持久化机制**：遵循 OpenRevo 沙箱插件存储引擎规范，运行时配置独立保存在 `%APPDATA%\OpenRevo\plugin_storage\cpu-guardian\config.json`。
